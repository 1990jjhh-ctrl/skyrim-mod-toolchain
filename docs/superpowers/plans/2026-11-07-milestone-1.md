# Milestone 1: Toolchain Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** skyrim-mod-toolchain provides the setup script, the pinned versions, the build helpers, format/lint scripts and the shared style configs, so that milestone 3 can move the three projects onto it.

**Architecture:** Plain files that a project uses from a git submodule (recommended path `lib/skyrim-mod-toolchain`). Bash scripts in `scripts/`, CMake files in `cmake/`, and the pins in `versions.env`, `vcpkg-configuration.json` and the `lib/commonlibsse-ng` submodule commit. Projects symlink `vcpkg-configuration.json`, `.clang-format` and `.clang-tidy`, include `cmake/CMakePresets.json` from their own presets, and include `cmake/commonlibsse.cmake` from their `CMakeLists.txt`. The toolchain's own tests are Python `unittest` modules that run the scripts with stub executables on `PATH` and a temporary `HOME`.

**Tech Stack:** Bash, Python 3 (stdlib only), CMake ≥ 3.25 presets (version 6, uses `${fileDir}`), vcpkg, xwin, llvm-mingw, shellcheck.

**Spec:** [docs/PRD.md](../../PRD.md). Milestone 1 covers R1–R12 and R14–R16. R13 (migrating the projects) is milestone 3; the CI action in R11 is milestone 2 and only has its inputs (the pins) prepared here.

## Global Constraints

- Linux host only; supported: Ubuntu/Debian (incl. GitHub `ubuntu-24.04`), and SteamOS through an Ubuntu distrobox.
- Every pinned version is defined exactly once in this repo (R6): tool versions and checksums in `versions.env`, the vcpkg baseline in `vcpkg-configuration.json` (`00c5775211f45cd08b37fce0484b4cb940e422ab`), CommonLibSSE-NG as the `lib/commonlibsse-ng` submodule commit (v13.1.0, `12d61f3c39f7d4ba1b1ab543df2bca0e613dc747`).
- Pins carried over: llvm-mingw `20260826` (`llvm-mingw-<ver>-ucrt-ubuntu-22.04-x86_64.tar.xz`), xwin `0.10.0` (prebuilt `xwin-<ver>-x86_64-unknown-linux-musl.tar.gz` from `github.com/Jake-Shadle/xwin`, not `cargo install`).
- Setup never runs `sudo` unless given `--install` (R2); everything else is installed under `$HOME` without root (R3).
- Default install locations stay those the projects use today: `~/.local/opt/llvm-mingw`, `~/xwin-out`, `~/xwin-cache`, `~/.local/share/vcpkg`. xwin's binary goes to `~/.local/bin`.
- Overridable locations: `LLVM_MINGW_BIN`, `XWIN_SYSROOT`, `VCPKG_ROOT` (as today). A set but invalid override is an error, never a fallback (R5).
- Python scripts use the standard library only. Shell scripts pass `shellcheck` and use tabs (`.editorconfig`).
- License headers: none per file; the repo is GPL-3.0-or-later.
- Commit titles follow `.gitlint` (Conventional Commits, ≤ 72 chars); one task = one or more commits on a branch per CONTRIBUTING.md.

## Review Focus

1. **Paths with spaces.** Steam libraries and some homes contain spaces. Every script must work with a `HOME` and a project path that contain a space. Test: Task 3 `test_home_with_space`, Task 7 `test_paths_with_space`.
2. **Interrupted download or extraction.** A partial llvm-mingw directory (exists, but `bin/x86_64-w64-mingw32-clang++` missing) or a partial xwin splat must be redone on re-run, not reported as "found". Tests: Task 4 `test_partial_llvm_mingw_is_reinstalled`, Task 5 `test_half_splat_is_redone`.
3. **Checksum mismatch.** A download whose sha256 doesn't match must abort and leave no install directory behind, so the next run doesn't take it for a good install. Test: Task 4 `test_checksum_mismatch_aborts_cleanly`.
4. **A user's own vcpkg.** When `VCPKG_ROOT` points at a vcpkg the user manages, at another commit, setup must not check it out or modify it; it warns that the commit differs from the baseline. Test: Task 5 `test_foreign_vcpkg_root_is_left_alone`.
5. **No C++ files under the given paths.** `clang-format` with no file arguments reads stdin and hangs. `format.sh` must report 0 files and exit 0 without calling it. Test: Task 7 `test_no_files_does_not_call_clang_format`.
