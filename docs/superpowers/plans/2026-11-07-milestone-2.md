# Milestone 2: Reusable CI Action Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A composite GitHub Action in the toolchain installs and caches the toolchain at the pinned versions, projects use it from their submodule, and the toolchain's own CI cross-builds `tests/consumer` through it on every pull request and push to `main`.

**Architecture:** `scripts/setup.sh` stays the only place that knows install locations and download names. It gains `--print-locations`, which prints those locations and cache keys as `key=value` lines. The action (`.github/actions/setup/action.yml`) reads them into step outputs, restores `actions/cache` entries at those paths, runs `setup.sh --install`, and exports the environment. A project calls it as `uses: ./lib/skyrim-mod-toolchain/.github/actions/setup` after a recursive checkout, so the action always matches the submodule pin.

**Tech Stack:** GitHub Actions composite action, Bash, `actions/cache@v6`, `actions/checkout@v7` (the versions trials-of-mastery's CI uses), Python `unittest`.

**Spec:** [docs/PRD.md](../../PRD.md), R11 and R12; success metrics "Pins in one place" and "No duplicated copies". User decisions for this milestone: projects reference the action by local path from the submodule (R12 is amended in Task 3), and the toolchain's CI runs the real cross build on every pull request and push to `main`.

## Global Constraints

- Every pinned value and install location is defined once (R6). The action contains no version, checksum, download URL or home-directory path. It gets locations and keys from `setup.sh --print-locations`, versions through `setup.sh`.
- The action never edits `versions.env`, `vcpkg-configuration.json` or project files.
- The runner is `ubuntu-24.04`. System packages come from `setup.sh --install` (`apt-get update` + `--no-install-recommends`), not from separate apt steps in the action.
- A cache restore must never make setup skip a step it would otherwise redo. setup's own checks stay authoritative: the llvm-mingw `.toolchain-version` stamp, the xwin version check, the sysroot `.splat-complete` stamp and the vcpkg baseline commit.
- Shell code passes shellcheck and uses tabs (`.editorconfig`). The test harness method is `run_script`.
- Conventional Commits per `.gitlint`. Work goes on branch `ci/setup-action` and lands through a pull request (CONTRIBUTING.md).

## Review Focus

1. **Paths with spaces in locations.** A `HOME` containing a space must give correct `key=value` lines: the value is everything after the first `=`, unquoted. Test: Task 1 `test_locations_with_space_in_home`.
2. **User overrides.** With `VCPKG_ROOT`, `XWIN_SYSROOT` or `LLVM_MINGW_BIN` set, the printed locations must be those values, so the action caches and exports what setup actually uses. Test: Task 1 `test_locations_follow_overrides`.
3. **Stale cache after a pin bump.** Changing `versions.env` must change the tools key. Changing `XWIN_VERSION` or the splat arguments must change the sysroot key. Changing the vcpkg baseline must change the vcpkg key prefix. Test: Task 1 `test_keys_change_with_pins`.
4. **`--print-locations` must be side-effect free.** No downloads, no git, no sudo, and no prerequisite check, because the action calls it before the tools exist. Test: Task 1 `test_print_locations_runs_nothing`.
5. **A project whose CMake source dir isn't the repo root** (skyrim-mcp's `plugin/`). The action's `source-dir` input must locate both the submodule and `vcpkg.json`. Test: Task 2 `test_action_uses_source_dir_for_vcpkg_json`. Proven for real in Task 4, because the toolchain's own CI uses `source-dir: tests/consumer`.

### Task 1: `setup.sh --print-locations`

**Files:**
- Modify: `scripts/setup.sh` (option parsing, new `print_locations`, `print_env` uses the same values, the splat arguments become one array)
- Create: `tests/test_setup_locations.py`

**Interfaces:**
- Produces: `scripts/setup.sh --print-locations` prints exactly these lines, in this order, and exits 0. It runs no other step and doesn't need any prerequisite.
  - `llvm_mingw=<dir>`: the managed llvm-mingw dir, or the parent of `$LLVM_MINGW_BIN` when that is the user's own.
  - `xwin_bin=<path>`: `$HOME/.local/bin/xwin`.
  - `sysroot=<dir>`: `${XWIN_SYSROOT:-$HOME/xwin-out}`.
  - `xwin_cache=<dir>`: `$HOME/xwin-cache`.
  - `vcpkg_root=<dir>`: `${VCPKG_ROOT:-$HOME/.local/share/vcpkg}`.
  - `vcpkg_archives=<dir>`: `${VCPKG_DEFAULT_BINARY_CACHE:-${XDG_CACHE_HOME:-$HOME/.cache}/vcpkg/archives}`.
  - `tools_key=<sha256 hex>`: sha256 of the versions file's content.
  - `sysroot_key=<sha256 hex>`: sha256 of `XWIN_VERSION` plus the splat argument list, so it changes when either changes.
  - `vcpkg_baseline=<40-hex>`: the baseline from `vcpkg-configuration.json`.
- Produces: `print_env` prints the same values as `--print-locations` (`LLVM_MINGW_BIN` = `<llvm_mingw>/bin`, `PATH` gets `dirname <xwin_bin>`). There is one helper that computes them, not two copies.
- Produces: the splat arguments are defined once (a bash array used by `install_sysroot` and by `sysroot_key`).

- [ ] **Step 1: Write the failing tests** in `tests/test_setup_locations.py` (ScriptCase; expose `sha256sum`, `python3`, `cut`, `awk`/`sed` as needed):
  - `test_prints_every_key_once`: the output parsed by `line.split("=", 1)` has exactly the keys above, in order.
  - `test_print_locations_runs_nothing`: with stubs for `curl`, `git`, `xwin`, `sudo` and `apt-get`, and with no prerequisites on `PATH`, the exit is 0 and none of the stubs is called.
  - `test_locations_follow_overrides`: `VCPKG_ROOT`, `XWIN_SYSROOT` and `LLVM_MINGW_BIN` set to temp dirs (the last one with a `bin/` subdir) are reflected in `vcpkg_root`, `sysroot` and `llvm_mingw`.
  - `test_locations_with_space_in_home`: `HOME=<tmp>/my home` gives values that start with that path, intact.
  - `test_keys_change_with_pins`: two temp versions files that differ only in `LLVM_MINGW_VERSION` give different `tools_key` and the same `sysroot_key`. Differing only in `XWIN_VERSION` changes both keys. Two temp vcpkg configs give different `vcpkg_baseline`.
  - `test_print_env_matches_locations`: the `export` lines from `print_env` (call it via `--source-only`) carry the same `VCPKG_ROOT`, `XWIN_SYSROOT` and `LLVM_MINGW_BIN` values as `--print-locations`.

### Task 2: Composite action

**Files:**
- Create: `.github/actions/setup/action.yml`, `tests/test_action.py`

**Interfaces:**
- Consumes: `setup.sh --print-locations` (Task 1).
- Produces: action `setup` with these inputs:
  - `source-dir`: the project's CMake source dir, relative to the workspace. Default `.`.
  - `native-tests`: `"true"` passes `--native-tests` to setup. Default `"false"`.
- Produces: action outputs `vcpkg-root`, `sysroot` and `llvm-mingw-bin`. After the action, `VCPKG_ROOT`, `XWIN_SYSROOT` and `LLVM_MINGW_BIN` are in `$GITHUB_ENV`, and `dirname xwin_bin` is in `$GITHUB_PATH`.
- Steps, in order:
  1. Run `"$GITHUB_ACTION_PATH/../../../scripts/setup.sh" --print-locations >> "$GITHUB_OUTPUT"`. The same step computes `vcpkg_key`, the sha256 of `<source-dir>/vcpkg.json` plus the toolchain's `cmake/triplets/*.cmake`.
  2. `actions/cache@v6` for `llvm_mingw` and `xwin_bin`, with key `skse-tools-<tools_key>`.
  3. `actions/cache@v6` for `sysroot`, with key `skse-sysroot-<sysroot_key>`. `xwin_cache` is not cached: the splat output is what the build needs, and the cache only feeds a re-splat.
  4. `actions/cache@v6` for `vcpkg_archives`, with key `skse-vcpkg-<vcpkg_baseline>-<vcpkg_key>` and restore-keys `skse-vcpkg-<vcpkg_baseline>-`.
  5. Run `setup.sh --install` (plus `--native-tests` when requested).
  6. Export the environment from the step 1 outputs.

  The toolchain root is reached only through `$GITHUB_ACTION_PATH`, never through a submodule path.

- [ ] **Step 1: Write the failing tests** in `tests/test_action.py`. These are text checks on `action.yml`, standard library only.
  - `test_action_has_no_pins_or_home_paths`: the file contains no value from `read_versions()`, no `vcpkg_baseline`, no `~/`, no `$HOME` and no `github.com/` download URL.
  - `test_action_calls_setup_through_action_path`: it contains `$GITHUB_ACTION_PATH/../../../scripts/setup.sh` (or `${{ github.action_path }}/…`), both with `--print-locations` and with `--install`.
  - `test_action_uses_source_dir_for_vcpkg_json`: the key step references `inputs.source-dir` together with `vcpkg.json`.
  - `test_cache_steps_use_location_outputs`: every `actions/cache@v6` `path:` value is a `steps.<id>.outputs.<key>` expression.
  - `test_shell_blocks_pass_shellcheck`: extract each `run: |` block (indentation-based) and give the substituted text to `shellcheck -s bash -`. Replace `${{ … }}` with a placeholder variable before checking.
- [ ] **Step 2: Run** `python3 -m unittest tests.test_action -v`. Expected: FAIL (file missing).
- [ ] **Step 3: Write `action.yml`** per the Interfaces block. Use `shell: bash` on every run step and quote every expansion.
- [ ] **Step 4: Run** `scripts/test.sh`. Expected: PASS.
- [ ] **Step 5: Commit** `feat(ci): add the reusable setup action`.
